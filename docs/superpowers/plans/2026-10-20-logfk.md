# logfk Implementation Plan

**Goal:** Complete the requested educational logging framework, including configuration,
destinations, buffering and a runnable demo, without another design approval round.

**Architecture:** Stable Logger/LoggerFactory API; immutable captured events; layouts
and destination appenders; optional bounded AsyncAppender decorator. LoggingContext
owns startup configuration, cached loggers and lifecycle. No static global singleton.

**Tech Stack:** Java 21, standard library, Maven, existing JUnit 5.
**Spec:** src/main/java/logfk/README.md, expanded by the user's 2026-10-20 request.
**Execution:** Implement in this session; preserve unrelated working changes.

## Global constraints

- Package logfk; keep the five original String convenience methods.
- Immutable startup config; defaults INFO + stderr; dot-boundary level inheritance.
- Constructor-injected Clock, appenders and error handler for deterministic checks.
- Operational destination failures are isolated; invalid API/config inputs fail fast.
- Critique belongs in source headers; record demonstrated progress in learning-plan.

## Review focus

- Concurrent close versus blocked async producers: reject new work and wake producers.
- Slow output during shutdown: bounded wait, no concurrent resource closure by caller.
- Partial startup failure: release every already-opened destination.
- Reentrant logging from formatting/error callbacks: contain recursive logging.
- Buffered output: flush/close drains; neither promises fsync or crash durability.
